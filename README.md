# Judo Competition

Платформа проведения турниров по дзюдо на русском и казахском. Next.js, NestJS, PostgreSQL/Prisma, WebSocket и независимое TypeScript-ядро. Текущие возможности и ограничения: [статус](docs/STATUS.md). Полный объём требований: [ТЗ](docs/TECHNICAL_SPECIFICATION_RU.md).

## Запуск

Node.js 24+, npm и отдельная база PostgreSQL 18+ с кодировкой UTF8. Миграция клубов использует NFKC и `pg_unicode_fast` для согласованной нормализации названий; требования этой сортировки описаны в [документации PostgreSQL 18](https://www.postgresql.org/docs/18/collation.html). Настройте `apps/api/.env` по `.env.example`, затем из корня:

```sh
npm ci
npm run db:generate
npm run db:migrate
node --env-file=apps/api/.env scripts/bootstrap-accounts.mjs
npm run dev
```

Сайт: http://127.0.0.1:4318. API: http://127.0.0.1:4319/api/v1. Публичной регистрации нет. Bootstrap создаёт отсутствующие аккаунты и выводит случайные пароли; существующие пароли сохраняются. Главный администратор создаёт организаторов на `/admin/users`.

Для production-сборки локально: `npm run build`; затем отдельно `npm run start -w @judo/api` и `npm start`. Не запускайте второй сервер API с той же базой. Для PDF необходимы каталог `apps/api/assets/fonts` с Noto Sans и лицензией и `apps/api/assets/brand/jcl-logo.jpg`.

## Работа с турниром

После входа открывается страница «Соревнования»: текущий турнир и история завершённых. Вся работа с татами, пультами и публикацией находится внутри турнира; отдельные пункты глобального LIVE и табло в меню отсутствуют.

1. Создать турнир и указать количество татами.
2. Добавить категории. В разделе «Участники» один раз выбрать или создать клуб и внести команду строками; проверить заявку и подтвердить сохранение состава уже взвешенных спортсменов.
3. Выбрать формат, проверить предварительные пары и подтвердить каждую сетку.
4. Проверить **«Распределение по татами»** в жеребьёвке и нажать **«Распределить автоматически»** либо сразу **«Запустить турнир»**. Сервер заполнит очереди свободными готовыми встречами и заблокирует составы.
5. Во вкладке **«Центр татами»** видеть все площадки, время и очереди; открыть **пульт**, **экран зрителя** или **ссылки и доступ оператора**.
6. Оператор начинает встречу, управляет оценками/временем и подтверждает результат. Зависимые встречи, публичная сетка и протокол получают подтверждённые данные автоматически.

Клубы имеют ID и относятся к текущему турниру. Клуб выбирается один раз; в редактируемых строках указываются фамилия, имя, год рождения, пол и явная категория. Можно добавить всю команду или позже дополнить её. Сохранённые составы и количество участников доступны по клубам и категориям на русском и казахском.

Необязательная вставка обычного текста добавляет строки в тот же черновик: `Фамилия;Имя;Год рождения;Пол;Точное название категории`. Вместо `;` допускается табуляция; заголовок необязателен. Пол — `MALE` / `FEMALE`, `М` / `Ж` или `ЕР` / `ӘЙЕЛ`. Неизвестная или неоднозначная категория остаётся пустой для ручного выбора. Программа не разбивает произвольное ФИО и не угадывает категорию. Файлы и Excel не используются; фактический вес и отметка взвешивания не обязательны.

Предпросмотр проверяет строки без записи в БД. После изменения строк или версии состава требуется новая проверка. Сохранение атомарное: до 500 строк в заявке и до 128 спортсменов в категории; ошибки не допускают частичной записи. Возможные совпадения требуют явного подтверждения отдельного спортсмена, записи не объединяются по имени. Сервер проверяет ID команды и revision, сохраняет исходный ответ и аудит; потеря ответа повторяет неизменную команду, а старый ответ не откатывает новый состав.

В сохранённом составе можно исправить одну заявку, явно сменить клуб или категорию, исключить участника в архив и восстановить исходные данные с тем же ID заявки. Исправление и восстановление проходят серверный preview с «Было / Будет»; исключение требует отдельного подтверждения. Для каждой операции обязательна причина от 3 до 500 символов. Сервер проверяет владельца, статус турнира `DRAFT`, неподтверждённые сетки исходной и целевой категорий и отсутствие ссылок на заявку во встречах; сохраняет версию, исходный receipt и аудит. Совпадения не объединяются автоматически.

Изменение состава переводит затронутую предварительную сетку в `STALE`: прежние snapshot/fingerprint сохраняются для истории, версия повышается. Подтверждение и выдача PDF сетки блокируются до новой генерации; подтверждение возвращает `DRAW_ENTRIES_CHANGED`. Массовые исправления и изменения после подтверждения сетки не реализованы. Общая идентичность спортсмена между турнирами/категориями остаётся следующим этапом.

Черновики добавления и неизвестные команды всех операций хранятся в `sessionStorage` этой вкладки и восстанавливаются после перезагрузки; это не постоянное хранение и не гарантия после закрытия вкладки. **Несохранённый черновик исправления заявки не сохраняется**; отправленная команда сохраняется до запроса и повторяется без изменения ID/revision/body. Старый маршрут индивидуального добавления оставлен для совместимости и имеет меньше гарантий, чем новый API состава; основной интерфейс использует новый сценарий.

Категория целиком закрепляется за одним татами. Новые категории распределяются по числу оставшихся схваток, включая будущие круги; уже закреплённые категории остаются на своих местах. Равное число встреч возможно не для каждого набора целых категорий. На каждом татами сначала проходит первый круг всех категорий, затем второй и далее. Внутри круга первыми идут младшие возрастные группы, внутри возраста — лёгкие веса. Начало следующего круга блокируется до завершения предыдущего; обязательный отдых сохраняется. Административный перенос отдельной встречи не меняет основное татами категории и её следующих встреч.

Публикация турнира для зрителей — отдельная кнопка. Внутри жеребьёвки каждой категории дополнительно нажмите **«Опубликовать сетку»**; там же её можно скрыть. Новая подтверждённая сетка первоначально скрыта. LIVE-табло и список участников не зависят от видимости сетки. Все татами, участники, сетки и результаты находятся на `/public/tournaments/[id]`. Отдельная страница `/public/tournaments/[id]/results` показывает призёров завершённых опубликованных категорий и автоматически обновляется. Круговые встречи доступны карточками по турам с таблицей побед и поражений. Кнопка «Скачать протоколы» открывает два доступных вида: **«Сетка»** (для круговой — пары по турам) и **«Все участники»** (списки по категориям). Можно выбрать одну, несколько или все категории и язык RU/KK. Остальные виды и общий пакет оставлены в окне с отметкой «Пока недоступно»; API отвечает `409 PROTOCOL_NOT_AVAILABLE`. Без параметра `kind` скачивается сетка. Сетка содержит пары, клубы, линии переходов, результат схватки и блок призовых мест после полного подтверждения категории. Большие сетки разделяются на читаемые листы, PDF содержит закладки. PDF отражает состояние на момент скачивания; для новых результатов скачайте его повторно.

Оценки добавляются нажатием на крупную ячейку и снимаются её кнопкой «−»; доступна отмена последней оценки. Центральное управление позволяет переносить встречи, снимать их с очереди, возвращать неподтверждённую встречу в очередь со сбросом счёта и отзывать подтверждение победы для исправления. Перед административным изменением указываются причина и последствия. Отзыв блокируется, если зависимая встреча уже началась или завершилась; журнал сохраняется.

Администратор работает в пульте под собственным аккаунтом. Для другого оператора создаётся одноразовое приглашение, ограниченное одним татами, с возможностью отзыва. Приглашение заменяет сессию в браузере: проверяйте его в отдельном профиле. Зрительские ссылки не дают управления. Сейчас адреса доступны только на этом компьютере; доступ с других устройств требует настройки сети и адреса сервера.

Рабочая модель по уточнению пользователя — **администратор и судья назначенного табло**. Отдельные главный судья и оператор турнира не требуются. Существующие технические роли `SUPER_ADMIN`/`ORGANIZER`/`OPERATOR` и аккаунты сохраняются до этапа 4; подписи текущего интерфейса пока отражают эту реализацию.

## Форматы

| Формат новых сеток         | Участники | Схема                                                      |
| -------------------------- | --------- | ---------------------------------------------------------- |
| Утешение от четвертьфинала | 8–128     | Основная сетка, утешение и две бронзовые встречи           |
| Круговая                   | 2–128     | Каждая пара один раз, дополнительные встречи при равенстве |
| Группы и плей-офф          | 8–128     | Минимум четыре группы, по два выхода, плей-офф с утешением |

Новые турниры используют пользовательский профиль `custom-2026-v3`: при 2–7 участниках любой выбранный формат превращается в круговую систему. При 8–128 доступны указанные выше форматы; оба варианта с утешением дают места 1, 2, 3, 3. Безутешительный формат доступен только для воспроизведения исторических сеток.

Равенство в новой круговой группе проверяется по победам и личным встречам; неразрешённое равенство создаёт дополнительные встречи и блокирует итог/выход из группы. Старые сетки сохраняют свой профиль, включая прежнее разрешение равенства порядком жребия. Соответствие официальному IJF не подтверждено. В выбывании клубы разводятся эвристикой; круговые встречи одноклубников обязательны.

## Структура

- `apps/web/src/app` — маршруты; `features` — турниры, клубный состав, жеребьёвка, LIVE, доступ, публичные страницы; `shared` — язык и события; `components/layout` — оболочка.
- `apps/api/src/modules` — отдельные модули auth, tournaments, roster, draws, matches, control, tatamis, public, protocols. Контроллеры проверяют DTO, сервисы выполняют команды с транзакциями и аудитом.
- `apps/api/prisma` — схема и миграции; `database` — доступ к PostgreSQL.
- `packages/engine` — расчёт жеребьёвки, зависимостей, мест и состояния схватки, без браузера и БД.
- `fixtures` — вымышленные тестовые составы; `scripts` — обслуживание и проверки.
- `docs` — актуальные требования/архитектура/статус; `archive` — история, не используется приложением.

Локальный Git инициализирован; проверенная версия исходников сохраняется в локальной истории. `.env` и приватные резервные копии БД исключены из истории.

## Проверяемая резервная копия PostgreSQL

Настройте `DATABASE_URL` в `apps/api/.env`. В `PATH` должны быть `pg_dump` и `pg_restore` той же основной версии, что сервер PostgreSQL. Учётная запись должна читать схему приложения, подключаться к служебной базе `postgres` и иметь право `CREATEDB` для создания отдельной проверочной базы.

```sh
pg_dump --version
pg_restore --version
npm run db:backup:verify
```

Команда читает исходную базу в согласованном read-only снимке и сохраняет архив. Восстановление выполняется только в новой базе со сгенерированным именем `qa_restore_…`; после сравнения она удаляется. Данные исходного турнира не изменяются. Сверяются строки и контрольные суммы таблиц, структура колонок, ограничений и индексов, включая `_prisma_migrations`.

Приватный дамп, манифесты и диагностика сохраняются в `tmp/backups/verified-…/`; каталог имеет права `0700`, файлы — `0600`. Публичный итог без учётных данных — [docs/reports/latest-backup-verification.json](docs/reports/latest-backup-verification.json). Успех означает совпадение восстановленной схемы и данных с экспортированным снимком и удаление проверочной базы; это не утверждение о последующих изменениях рабочей БД.

Последняя проверка после миграции исправлений этапа 3а прошла для 14 таблиц и структуры; восстановленная QA-база удалена. Приватный архив: `tmp/backups/verified-2026-10-09T08-52-53.132Z-3e78a6ab/database.dump`.

Проверка рассчитана на текущую схему приложения с UUID и таблицами: данные и записи миграций, колонки с точностью времени, ограничения и индексы. Различие SQL NULL и JSON null учитывается. При появлении неподдерживаемых объектов — последовательностей, функций, пользовательских триггеров, enum, представлений или собственных сортировок схемы — проверка завершается ошибкой, а не объявляет копию проверенной. Журналы IndexedDB на устройствах, fonts/brand и другие assets, настройки сервера и права пользователей PostgreSQL в этот прогон не входят. Сетевая инфраструктура, сбой оборудования и восстановление в зале проверяются отдельно.

## Проверки и демонстрация

`npm run test:rehearsal` проводит полный серверный прогон в отдельной временной схеме PostgreSQL и на отдельном порту. Проверяет чистую/повторную установку миграций, доступы, сетки, очереди, табло, исправления, публикацию и PDF; реально аварийно останавливает только свой API для проверки сохранения схватки и подтверждённого результата. Рабочие турниры не изменяются. После прогона временная схема удаляется, журнал и контрольный PDF остаются в `tmp/rehearsal/`, последний отчёт — `docs/reports/latest-rehearsal.json`. Требуется работающий PostgreSQL и `apps/api/.env`.

Для миграций используйте `npm run db:migrate`: команда сначала применяет базовые миграции, затем поздние 007/008. Имена и контрольные суммы ранее применённых миграций сохраняются. Прямой запуск `prisma migrate deploy` на пустой базе не учитывает исторически смешанные имена папок.

```sh
npm run check
# При запущенных API и сайте, только на базе разработки:
npm run test:integration
npm run test:auth
npm run test:draws
npm run test:public
npm run test:protocols
npm run test:live
npm run test:formats
npm run test:control
npm run test:scheduling
npm run test:150
```

`check`: формат, границы импортов всех приложений, строгие типы, тесты ядра/интерфейса/серверных команд/служебных скриптов и production-сборка. Регрессии серверных команд в `test:api` не требуют подключения к БД. Полную проверку с PostgreSQL выполняйте через изолированный `test:rehearsal`; он включает интеграционные сценарии и перезапуски. Отдельные интеграционные тесты создают временные турниры и удаляют только свои данные. `test:150` относится к историческому демонстрационному турниру.

Актуальные подготовленные данные описаны в `docs/STATUS.md` и отчётах EVEREST/MINI CUP. Старый демонстрационный турнир на 150 вымышленных участников удалён ранее по запросу пользователя; `docs/reports/current-demo.json` — исторический отчёт. Для явного полного сброса данных разработки существует `npm run demo:reset -- --reset-all-tournaments`: команда сохраняет резервную копию, удаляет **все турниры и составы**, сохраняет аккаунты и создаёт новый набор в состоянии подготовки. Не запускается автоматически.

Ограничения до реальных соревнований: испытания автономной работы на оборудовании зала, полный набор исключительных судейских решений, каскадное исправление проведённых зависимых встреч, единая идентичность спортсмена между категориями и проверенные версии регламента. Подробности в [статусе](docs/STATUS.md).

### Observable MINI CUP rehearsal

`npm run test:mini:prepare` creates a separate published synthetic tournament: 34 athletes, 5 categories, 3 tatamis, 47 bouts. Formats: 2-person final, 7-person knockout with BYE, 12-person repechage, 5-person round robin, 8-person mixed pools/knockout. Duplicate preparation is rejected.

`npm run test:mini:run` uses the normal API to complete it, retaining results for inspection. It checks actual 5/10/20-second holds, score/result corrections, third Shido, repeated commands, bracket progression, WebSocket and public results.
