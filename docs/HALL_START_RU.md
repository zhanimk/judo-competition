# Как запустить турнир и подключить зал

## Сейчас — на этом Mac

1. Подключите Mac к питанию. База PostgreSQL должна быть запущена, как при текущей проверке.
2. В папке проекта дважды нажмите **«Запустить турнир.command»**. Оставьте окно открытым. Если сайт уже запущен, программа сообщит об этом и не остановит его.
3. Откройте Safari: **http://127.0.0.1:4318**. Публичная часть: **http://127.0.0.1:4318/public**.
4. Для остановки нажмите **Ctrl+C** в окне запуска. Перед выключением дождитесь остановки. Закрытие Safari сервер не останавливает.

Запуск проверяет сборку, свободные порты и состояние миграций. Он не сбрасывает данные и не применяет миграции автоматически. Если сообщает об ошибке, сохраните текст сообщения; технические журналы находятся в `tmp/local-run`. Пароли публиковать не нужно.

## Что понадобится в зале

- Этот Mac — главный сервер и рабочее место администратора.
- Один общий роутер Wi-Fi, питание и зарядные устройства. По возможности Mac подключить к роутеру кабелем.
- По ноутбуку на каждое судейское татами.
- ТВ: проще подключить HDMI к отдельному ноутбуку, открыв на нём зрительское табло.
- Принтер: подключить к Mac и сначала распечатать обычную пробную страницу.

Интернет для обмена внутри зала не нужен. Все устройства должны быть в одной обычной сети, не в гостевой сети с изоляцией клиентов. Адрес `127.0.0.1` работает только на главном Mac: на судейском ноутбуке нужен общий адрес сервера.

## Однократная настройка перед соревнованием

Эта часть требует доступа к роутеру и судейским устройствам; её нельзя закончить без них.

1. Закрепить за Mac постоянный локальный адрес в настройках роутера.
2. Настроить единый **HTTPS-адрес** сервера и доверие сертификату на каждом ноутбуке. Подробная конфигурация: [DEPLOYMENT_RU.md](DEPLOYMENT_RU.md). Локальный запуск выше сам по себе не открывает сервер для других устройств.
3. Разрешить входящий HTTPS в брандмауэре. Базу, Redis и прямой API не публиковать. Работает только один сервер API.
4. Открыть общий адрес на каждом ноутбуке. Из управления турниром выдать судье доступ именно к его татами. Проверить вход и отсутствие управления чужим татами.
5. Открыть зрительское табло на экране ТВ. Проверить читаемость имён, всех оценок и таймера с места зрителей.
6. Подключить питание, запретить автоматический сон главного Mac на время соревнования. Не менять сеть во время работы.

Не нужно устанавливать копию сервера или базы на судейские ноутбуки. Доступ извне зала и публикация сайта в интернете — отдельная настройка, не обязательная для локального турнира.

## Обязательная проба на месте

Все пункты ниже пока **не приняты на реальном оборудовании**:

- [ ] Судья начинает и завершает тестовую схватку своего татами; изменения видны администратору и на ТВ.
- [ ] Отключён только внешний интернет: локальные пульты и табло продолжают работать.
- [ ] Один судейский ноутбук теряет Wi-Fi и подключается снова: выполнена сверка автономного журнала, нет двойных команд.
- [ ] После штатной остановки и запуска сервера результаты сохранены; ранее работающий таймер требует контролируемой сверки.
- [ ] Создана резервная копия и проверено восстановление в отдельную базу; оригинал не заменён.
- [ ] Распечатаны сетки и результаты, участники по категориям и командный зачёт; публично скачиваются только опубликованные документы.
- [ ] Ответственный знает, где резервная копия, кто заменит его и как остановить/запустить сервер.

До этих проверок приложение нельзя считать принятым для проведения соревнования в зале.
