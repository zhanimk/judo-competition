# Строгая проверка движка — 16 октября 2026

## Результат

Проведена проверка спортивного ядра `packages/engine` и его серверного применения. Обнаружены и исправлены две технические ошибки. В проверенных сценариях ошибок продвижения или распределения медалей не выявлено. Это результат перечисленных испытаний, а не доказательство отсутствия любых ошибок и не сертификация IJF. Проверяется согласованный пользовательский профиль v6; исторические snapshots сохраняют свою политику.

## Найденные ошибки

| Ошибка                                                      | Воспроизведение до исправления                                                                         | Исправление и практический риск                                                                                                                                                                                                               |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Неизвестная политика сетки молча использовала LEGACY        | Передать `UNKNOWN_PROFILE` вместо известной политики: при шести участниках создавалась старая круговая | Теперь `DRAW_POLICY_UNSUPPORTED`. Защищает от опечаток и некорректной конфигурации. LEGACY, REPECHAGE_ONLY, KNOCKOUT_FROM_SIX и отсутствие аргумента сохраняют прежнее поведение.                                                             |
| Суммирование времени Golden Score могло дать неточное число | После `Number.MAX_SAFE_INTEGER` миллисекунд добавить ещё 1: сохранялось небезопасное целое             | Накопленное время Golden Score и удержания проверяется до изменения состояния; недопустимое увеличение даёт `INVALID_TIME`. Это числовой крайний случай, не наблюдавшийся сбой обычного турнира. Спортивный лимит Golden Score не добавлялся. |

Обе ошибки сначала подтверждены падающими регрессионными тестами, затем эти же тесты прошли. Входное состояние при отклонённой команде не меняется.

## Независимые проверки

- **640 полных вариантов исходов** сеток 6/7: все варианты победителей, доступность зависимостей, отдельные финалисты, перекрёстные полуфиналисты в бронзе, четыре разных призёра, отсутствие итогов до последнего результата.
- **1098 вариантов круговых исходов** для 2–5: независимый подсчёт числа побед; для каждого равенства дополнительная встреча либо явно заданный порядок группы. Полученный порядок сравнивается с отдельным расчётом, а не с другим вызовом той же функции. Медальные места для 4/5 — 1, 2, 3, 3; пятый без медали.
- **1792 сценария снятия** в сетках 6/7: каждый набор снятых участников перед стартом и после каждого префикса подтверждённых встреч. Исторические победители неизменны; снятые не выходят в реальные следующие пары и не получают мест; пустые ветви завершаются; повторный расчёт проходов не добавляет новых действий.
- **72 сравнения шага времени**: обе стороны, основное время/Golden Score, с предшествующим ваза-ари и без него, непосредственно до/на/после порогов удержания. Один большой ADVANCE и последовательность шагов по 137 мс дают одинаковые оценки, исход, часы и состояние удержания. Проверено удержание через окончание основного времени.

Исходник новых проверок: `packages/engine/test/strict-audit.test.ts`. Они запускаются обычной командой тестов ядра.

## Существующая матрица, запущенная повторно

Ядро проверяет генерацию и BYE, круговые пары и отдых по кругам, сетки до 128 участников, MIXED и выход из групп, утешения, зависимости победителей/проигравших, дополнительные круги, ручные решения, снятия и пустые ветви, оценки и отмены, три шидо, удержания, Golden Score, коррекцию остановленных часов, идемпотентность и конфликты команд, распределение нагрузки и порядок возрастов/весов.

Полный `npm run check` прошёл: **545 тестов** — 79 ядра, 164 web, 35 скриптов, 267 API; также форматирование, границы модулей, TypeScript и production build.

Серверная репетиция запускается отдельно через `npm run test:rehearsal` в новой одноразовой QA-схеме PostgreSQL. Итоговый машинный отчёт: [latest-rehearsal.json](latest-rehearsal.json). В неё входят настоящий HTTP API, публикация/PDF, права/версии/повтор команд, автономная синхронизация, аварийные и штатные перезапуски, резервное копирование и восстановление. Рабочие турниры для неё не используются.

## Границы заключения

- Нет автоматического сравнения оценок/шидо для круговых мест. Для трёх и более это только явное решение администратора с серверной процедурой; для двух — новая встреча.
- Три шидо завершают только текущую схватку; снятие из турнира — отдельная операция. Проходы не создают фиктивные очки и отдых.
- Выбранная большая круговая от 8 участников сохранена намеренно. MIXED и части олимпийского дерева A/B/C/D — разные системы.
- Ядро не выполняет авторизацию, аудит БД или управление устройствами: эти барьеры проверяются на сервере. Число победителей само по себе не заменяет подтверждение результата и транзакцию.
- Реальные судейские устройства, питание, Wi-Fi, доверенный HTTPS, ТВ и принтер этой проверкой не принимаются. Долгая нагрузка всего зала и физический обрыв питания требуют отдельной приёмки.
