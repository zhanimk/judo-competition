# Воспроизводимый аудит ядра

Скрипт [engine-audit.mjs](../../scripts/engine-audit.mjs) читает собранное ядро только через публичные `@judo/engine/draw` и `@judo/engine/match`. Сервер, браузер и база данных не используются. JSON выводится в stdout; сохранённый результат — [latest-engine-audit.json](latest-engine-audit.json).

Запуск из корня репозитория с Node.js 24 или новее:

```sh
npm run build -w @judo/engine
node scripts/engine-audit.mjs > docs/reports/latest-engine-audit.json
```

Перед общей проверкой форматирования сохранённый JSON приводится к стилю репозитория: `npx prettier --write docs/reports/latest-engine-audit.json`. Это меняет только оформление отчёта.

Проверяются 1 143 завершённые сетки: 2–128 участников, запросы `ROUND_ROBIN`, `REPECHAGE`, `MIXED`, seeds `0`, `1`, `4294967295`, политика `REPECHAGE_ONLY`. Победитель каждой доступной пары выбирается по порядку ID. Проверяются уникальность встреч, разные стороны из пары, допустимый победитель, отсутствие повторного спортсмена в обычном раунде, число круговых встреч и уникальность итоговых получателей мест.

В 600 сериях выполняются 54 000 попыток команд с фиксированным seed `20261010`, включая удержания, отмены, подтверждение, восстановление и исправление остановленного времени. Проверяются версии, границы времени, связь статуса с исходом, ограничения оценок и неизменность входа при отклонённой операции. Число принятых и отклонённых действий отражает текущую реализацию и может измениться после её исправления. Дата в JSON обозначает фиксированную серию аудита, а не время каждого повторного запуска.

Две отдельные репродукции показывают разрешение равного числа побед личной встречей в исторической политике и номера дополнительных раундов при тройном цикле в группе MIXED. Это наблюдения для согласования и версионирования правил. Статусы `observed`, `resolved`, `needs_review` описывают конкретную репродукцию; исправление известного расхождения само по себе не ломает скрипт. Они не означают готовность всего формата или проекта.

Обход результатов не исчерпывающий: для сеток выбран один детерминированный путь победителей. Инварианты состояния не являются независимым спортивным эталоном; не проверяются все сочетания команд и регламентов. Аудит не подтверждает официальный профиль IJF, реальные гонки PostgreSQL, восстановление после падения сервера, автономную синхронизацию, доставку LIVE, PDF, интерфейс или оборудование зала. Итоги относятся к собранному ядру на момент запуска; для проверки изменённых исходников сначала нужна сборка.
