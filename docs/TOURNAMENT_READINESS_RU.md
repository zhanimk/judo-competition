# Приёмка для реального турнира — 16 октября 2026

## Решение по готовности

Запуск реального турнира пока не принят: требуется развёртывание и генеральная репетиция на оборудовании зала. Реализованы ручные места среди трёх и более равных и удаление из дальнейших встреч с автоматическими проходами. Проверки одной машины не подтверждают работу Wi-Fi, ноутбуков судей, телевизоров и принтера.

Аудит опирается на текущий код, `TECHNICAL_SPECIFICATION_RU.md`, `AGENTS.md` и повторный запуск проверок. Старые разделы `STATUS.md` и README описывают предыдущие версии и местами отстают от кода.

## Дополнение по последним ответам пользователя

Ручная сверка v4 теперь разрешает либо дополнительный круг, либо полный порядок мест внутри равной группы с причиной. Автоматического сравнения оценок/шидо нет. Решение не создаёт фиктивных встреч; завершение категории/турнира, публичные места и PDF используют единый расчёт ядра.

Удаление в разделе сеток прекращает дальнейшую борьбу: соперники проходят без схватки, оба удалены — пустая ветвь без победителя и проход следующего соперника. Сыгранные результаты, заявки и ID сохраняются. Новые WALKOVER/NO_CONTEST не начисляют иппон и отдых; WITHDRAWAL из начатой остановленной встречи сохраняет отдых. Удалённые не получают места. После начала MIXED-плей-офф сохраняется утверждённый выход из групп. Удаления до запуска, полностью разрешившие категорию, не оставляют турнир зависшим в RUNNING.

Команды требуют причины и preview, связанного с актором, версией и состоянием, и применяются транзакционно с receipt/аудитом/outbox. Работающий таймер, удержание, offline-владение и изменяемые начатые зависимости блокируют действие. Неизвестный пакет сохраняется в браузере для точного повтора/выгрузки.

Границы: v4 и незавершённый турнир; старые профили не мигрируются автоматически. Возврат удалённого и пересмотр сыгранных результатов категории с удалениями требуют отдельной процедуры, обычный REOPEN блокируется. Расширенная модель травм и прямого Hansoku-make не включалась. Три шидо остаются поражением одной схватки.

## Оставшиеся этапы до допуска

1. **Развернуть топологию зала.** Главный ноутбук с сервером/БД, остальные с пультами через Wi-Fi. Настроить стабильный адрес, доверенный HTTPS, доступ между устройствами, питание и резервную копию. Инструкция — `DEPLOYMENT_RU.md`.
2. **Проверить интерфейс на устройствах.** Администратор, судьи, ТВ, мобильный экран, RU/KK, удаление с предпросмотром, ручные места и печать PDF. Автоматические тесты не заменяют приёмку устройств.
3. **Провести репетицию отказов.** Потеря интернета при сохранённой LAN, разрыв LAN, сон/перезагрузка пульта, unknown-response, восстановление API/Redis/БД, сверка времени и offline-журнала. Неполные исторические offline-метаданные блокируются; универсального ремонта нет.
4. **Провести генеральный турнир.** Ввод → сетка → все форматы → удаление одного/обоих → автоматические проходы → дополнительные встречи/ручные места → публикация → PDF/медали. Независимо сверить результаты и измерить задержки команд/LIVE и часов под ожидаемой нагрузкой.

## Проверки этого аудита

Последний прогон отказоустойчивости описан в [STATUS.md](STATUS.md#проверка-отказоустойчивости-16-октября): **530 тестов**, 84 полных v4-сетки, семь аварийных и два штатных перезапуска API в сценариях сохранности, отдельный production-стенд с настоящим Redis и браузерное восстановление автономной схватки после отключения QA-веб-сервера. Старые числа ниже относятся к предыдущим прогонам. Приёмка Wi-Fi и физического питания зала остаётся обязательной.

`npm run check` прошёл после дополнения: **516 тестов** (ядро 69, web 156, скрипты 28, API 263), строгие типы, форматирование, границы зависимостей и production-сборки. Проверка выполнена с разрешением управлять собственными дочерними процессами после sandbox EPERM в тесте завершения процессов. Серверная репетиция новых сценариев также прошла: 30 проверок, `passed: true`, `cleanedUp: true`. Актуальные логи дополнения — `tmp/removal-check.log` и `tmp/removal-rehearsal.log`.

Изолированная серверная репетиция: актуальный результат находится в [latest-rehearsal.json](reports/latest-rehearsal.json); принимать только `passed: true` и завершённую очистку QA-схемы. Проверка запускает отдельный API и отдельную случайную схему, рабочие турниры не меняет. Логи текущего аудита — `tmp/readiness-check.log` и `tmp/readiness-rehearsal.log`.

Финальный прогон 16 октября прошёл: **30 проверок в отчёте**, включая чистые/повторные миграции, прикладные интеграционные наборы, два аварийных и один штатный перезапуск API, восстановление зашифрованной копии и отдельную проверку резервной копии с последовательностью outbox и байтами PDF. `passed: true`, `cleanedUp: true`. Проверка RR128 использует 8127 синтетических исторических результатов и одну настоящую заключительную встречу через HTTP; это не репетиция 8128 реальных схваток. Статическая проверка Compose с HTTPS также прошла; контейнеры на целевом хосте и оборудование зала этим прогоном не проверялись.

Исправлено при аудите: тестовый клиент одиночного ввода передаёт ID и версию состава; тестовый сервис получает RosterService; синтетические спортсмены разных категорий имеют разные имена вместо неподтверждённых совпадений. Для подтверждённой сетки одиночный ввод возвращает `409 DRAW_LOCKED`; точный старый receipt остаётся доступным. Добавлена регрессия сохранности состояния и повтора после подтверждения сетки. Проверки прав и спортивные ограничения не ослаблялись.

Дополнительно обновлены административная fixture одиночного ввода, учёт отдельного LIVE-события публикации турнира в тесте PDF и проверка отката outbox через существующее поле `venue` вместо отсутствующего `description`. Прикладные наборы не исключались из репетиции.

## Что не входит в текущий допуск

Файловый импорт, встроенное взвешивание, балльный командный зачёт и новые рабочие роли исключены пользовательскими требованиями. Сертификация официального профиля IJF не выполнена и для пользовательского регламента не заявляется. Массовое изменение состава после подтверждения и каскадное переписывание проведённых зависимых встреч не должны появляться как неограниченный обход спортивных защит.
