# Правила разработки Judo Competition

- Источник требований: docs/TECHNICAL_SPECIFICATION_RU.md и последние указания пользователя.
- Целевой стек: Next.js/TypeScript, NestJS, PostgreSQL/Prisma, Socket.IO, Redis, IndexedDB, Docker. Не заменять готовый сервер демонстрационной логикой.
- Монорепозиторий: apps/web/src/app — маршруты, apps/web/src/features — функциональные модули интерфейса, apps/api — сервер, packages/engine — независимое спортивное ядро без React/БД/DOM. archive — только исторические стенды, не входит в рабочие команды.
- Предметные функции интерфейса группировать по features; компоненты отображения отделять от адаптера команд/времени и доменного расчёта.
- Ориентир табло: белая горизонтальная строка сверху, синяя снизу, таймер снизу на тёмной полосе; флаг Казахстана и KAZ у обоих спортсменов (обновлённый ориентир пользователя). Все четыре оценки крупные, с постоянными читаемыми подписями, включая нули. Цвет дополняет текст. Адаптация для мобильных и ТВ обязательна.
- Не называть непроверенный профиль официальным IJF. Помечать демонстрационные данные и отсутствие долговременного хранения.
- TypeScript strict; проверять typecheck, тесты ядра и production build при изменении соответствующих частей.
- Критические команды проверяет сервер. Нужны идемпотентность, версии, аудит и проверка зависимостей. Клиентское состояние не заменяет эти механизмы.
- Реализованные возможности и пробелы описывать честно; не объявлять прототип готовым соревнованием.

- Новые изменения проверять командой npm run check. Не импортировать внутренние файлы ядра из приложений: только публичные exports @judo/engine. Демоданные держать в fixtures, не в доменном ядре.

- Пользователь вносит уже прошедших взвешивание спортсменов. В текущем этапе не добавлять встроенное взвешивание, обязательный фактический вес или блокировку отсутствия отметки о взвешивании.

- Excel и другие файловые импортёры исключены пользователем. Администратор вводит участников по одному; будущий массовый сценарий — вставка обычного текстового списка всей команды с предпросмотром, проверкой и отдельным подтверждением. Клуб и категории задаются явно; категории не угадывать, возможные дубликаты не объединять автоматически.

- Две рабочие роли: администратор и судья назначенного табло. Администратор управляет турниром, составом, исключительными исправлениями и доступом; судья ведёт схватки только своего татами. Не добавлять отдельного главного судью или оператора турнира. Технические роли и существующие аккаунты сохранять до согласованного этапа изменения доступа.

- Три пользовательских вида PDF: сетки и результаты (до соревнования пары, после подтверждения категории — призовые места с ФИО и клубом), участники по категориям, итоговый командный зачёт по медалям. Отдельные протоколы схваток/итогов, отдельный медальный зачёт и общий комплект исключены. Баллы отложены; ранжирование команд — золото, затем серебро, затем бронза, равные показатели дают общее место. Публичное скачивание только опубликованных документов остаётся обязательной доработкой.

- Очередь каждого татами: первый круг всех категорий, затем второй и далее; внутри круга младшие возрастные группы и лёгкие веса первыми. Категория закреплена за татами; автоматическое распределение новых категорий учитывает число оставшихся встреч и сохраняет закрепления. Перенос отдельной встречи не переносит всю категорию. Проверки порядка и отдыха обязательны на сервере.

- Три шидо означают проигрыш только текущей схватки: спортсмен сохраняет возможность продолжить по сетке, включая борьбу за бронзу, если формат допускает. Администратору требуется отдельное снятие спортсмена во время турнира с причиной и проверкой последствий; не подменять его удалением личности или исторических встреч. Последствия для ещё не сыгранных пар, группового выхода и итоговых мест согласовываются отдельно.

- Исправление ФИО активной заявки после подтверждения сетки, во время турнира и после его завершения — отдельная операция администратора с причиной, ID команды, версией, receipt и аудитом. Она меняет только firstName/lastName текущей Entry: ID спортсмена/заявки, другие турниры, клуб, категория, спортивное состояние, сетка и результаты сохраняются. Обновлять отображение по стабильным ID; автономный спортивный журнал и исходный pending-пакет не переписывать ради новых имён. Без сети новые имена доступны только после получения актуального снимка; скачанный PDF остаётся снимком.

- Последнее требование пользователя: единое поведение табло, оценок, удержания и Golden Score во всех категориях; различается длительность основного времени. Это уже реализовано единым custom-2026-v3 и должно сохраняться. Круговое ранжирование — только число побед: двое с равным числом побед получают дополнительную встречу независимо от личной встречи; трое и более требуют ручного решения администратора. Не выбирать места автоматически по личным встречам, оценкам или жребию. Текущее ранжирование v3 ещё не соответствует этому правилу; ближайший этап — v4 с новой политикой равенства, процедурой ручной сверки и согласованными серверными барьерами стадий перед внедрением снятий. Исторические snapshots не менять молча.

- Уточнение 16 октября 2026 имеет приоритет над историческим планом выше: v4 реализован. При равенстве трёх и более администратор может вручную задать полный порядок мест внутри равной группы с причиной (в том числе по оценкам/шидо) либо назначить дополнительный круг. Для двух равных — дополнительная встреча. Автоматического приоритета оценок/шидо нет.
- Удаление после подтверждения означает убрать из дальнейшей борьбы, передать будущим соперникам проход без схватки и сохранить сыгранную историю/ID. Если убраны оба, ветвь не имеет победителя, следующий соперник проходит автоматически. Фиктивные оценки не добавлять; новые проходы не создают отдых. Начатый MIXED-плей-офф сохраняет утверждённый выход из групп. Действия требуют причины, preview, версии, receipt и аудита; несверенный offline-журнал, работающий таймер/удержание и начатые изменяемые зависимости блокируют операцию. Три шидо не являются удалением из турнира.
- Топология зала: главный ноутбук с сервером и административным интерфейсом, остальные ноутбуки с пультами через общий Wi-Fi. Локальная работа без интернета обязательна; проверка HTTPS и реального оборудования остаётся отдельной приёмкой.
